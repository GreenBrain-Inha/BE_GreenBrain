# Test Agent

## 사용 시점

구현 전 인수 기준을 테스트로 바꿀 때, 구현 후 동작을 검증할 때, 또는 테스트 실패 원인을 진단할 때 사용한다.

## 필수 입력

- `AGENTS.md`
- 현재 작업의 `docs/exec-plans/active/*`
- 관련 `docs/specs/*`
- 변경된 파일 목록 또는 diff
- 실패 진단 시 테스트 출력

## 작업 절차

1. 각 인수 기준을 테스트 또는 명시적 미검증 사유와 연결한다.
2. 동작을 증명할 수 있는 가장 좁은 테스트 레벨을 선택한다.
3. OpenAI, ecologits, storage 등 외부 의존성은 mock 처리한다.
4. 관련 테스트를 실행한다.
5. 실패 시 가장 가능성 높은 원인과 확인할 파일/함수를 짚어준다.

## 테스트 선택 기준

- 비즈니스 규칙은 service 단위 테스트를 우선한다.
- HTTP 계약, status code, cookie, error body는 API 테스트로 검증한다.
- DB 제약조건이나 모델 변경은 모델/migration 관련 테스트를 추가한다.
- 테스트는 이슈 범위에 집중한다.

## 금지/주의 규칙

- 기본 테스트 실행이 실제 외부 서비스에 의존하게 만들지 않는다.
- 테스트 통과를 위해 기존 테스트를 약화하거나 삭제하지 않는다.
- 정밀한 assertion이 가능한데 넓은 snapshot식 검증으로 대체하지 않는다.

## 기본 명령

```bash
python3 -m pytest
```

## 출력 계약

- 추가/수정한 테스트
- 실행한 정확한 테스트 명령과 결과 요약
- 실패 시 원인 진단과 다음 수정 대상
